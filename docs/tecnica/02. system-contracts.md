# 02. Contratos y Acuerdos de Comunicación — NEXO MAP
## NEXO MAP — Sistema de Reporte y Seguimiento de Incidentes Territoriales (Formosa)

Este documento constituye el **acuerdo formal y vinculante** entre la aplicación móvil ciudadana (NEXO MAP Mobile), el panel web administrativo (NEXO MAP Admin Web) y el backend en FastAPI. Ningún cliente debe implementar endpoints no documentados ni inventar formatos de datos por fuera de este contrato.

---

## 1. Convenciones Generales de Comunicación HTTP

### 1.1. URL Base y Versionado
- **Entorno de Desarrollo:** `http://localhost:8000/api/v1` (o IP local de red para testing en dispositivos físicos, ej: `http://192.168.1.50:8000/api/v1`).
- **Entorno de Producción:** `https://api.nexomap.formosa.gob.ar/api/v1` (o dominio asignado).
- **Versionado:** Estricto en el prefijo de la ruta: `/api/v1`. Cualquier cambio no retrocompatible exigirá `/api/v2`.

### 1.2. Formato de Cargas y Convención de Nombres
- **Formato:** JSON (`application/json; charset=utf-8`) para todas las solicitudes y respuestas, salvo la creación de reportes con fotos que utiliza `multipart/form-data`.
- **Casing:** Estricto `snake_case` para todas las claves de objetos JSON en solicitudes y respuestas.
- **Identificadores:** 
  - Claves primarias técnicas: UUIDv4 canónico en minúsculas (ej: `"a3b8d4e2-7c1f-4b9a-8e2d-9f1e8a7b6c5d"`).
  - Número de reporte amigable para el usuario: Cadena formateada con almohadilla y 5 dígitos (ej: `"#00142"`).

### 1.3. Manejo de Fechas y Zonas Horarias
- **En la Red y Base de Datos:** Formato estricto **ISO 8601 UTC** (`YYYY-MM-DDTHH:mm:ss.sssZ`).
- **En la Interfaz de Usuario:** Los clientes (Móvil y Web) deben transformar las marcas de tiempo a la hora oficial de la República Argentina (**UTC-3**, zona `America/Argentina/Cordoba` o `America/Argentina/Buenos_Aires`).
- **Formato Visual Estándar:** `DD/MM/AAAA (HH:MM)` (ejemplo: `18/11/2026 (15:30)`).

### 1.4. Formato Estandarizado de Errores (RFC 7807)
Todo código de error HTTP ($\ge 400$) debe retornar obligatoriamente la siguiente estructura JSON:

```json
{
  "error": {
    "code": "OUTSIDE_TERRITORY",
    "message": "La coordenada especificada no pertenece al territorio de la provincia de Formosa.",
    "details": {
      "latitude": -25.2987,
      "longitude": -56.8921
    },
    "timestamp": "2026-11-18T18:30:00.000Z"
  }
}
```

### 1.5. Convención de Paginación
Para endpoints con listados múltiples, la paginación se parametriza mediante Query Params:
- `page` (entero, $\ge 1$, por defecto `1`).
- `page_size` (entero, entre `1` y `100`, por defecto `20`).

Estructura de respuesta paginada:
```json
{
  "items": [],
  "pagination": {
    "page": 1,
    "page_size": 20,
    "total_items": 85,
    "total_pages": 5,
    "has_next": true,
    "has_prev": false
  }
}
```

## 2. Diccionario de Datos y Enumeraciones

### 2.1. Estados del Reporte (`ReportStatus`)
Flujo de ciclo de vida del reporte:
1. `pendiente`: Recibido automáticamente por el sistema, a la espera de ser evaluado.
2. `en_revision`: Un administrador ha tomado el caso y lo está evaluando activamente.
3. `verificado`: El incidente fue confirmado como verídico en el terreno.
4. `descartado`: El aviso no corresponde a un incidente real, es duplicado o inverificable.
5. `en_seguimiento`: Se están coordinando o ejecutando tareas operativas/reparaciones sobre el incidente.
6. `resuelto`: El incidente fue atendido y la situación quedó subsanada.

### 2.2. Categorías del Incidente (`IncidentCategory`) y Colores Oficiales
Los colores identificativos de las categorías se preservan exclusivamente para marcadores cartográficos, polígonos de concentración e indicadores funcionales de categoría. El sistema visual general de interfaces, botones y tipografía está gobernado por [docs/08. visual-design-system.md](08.%20visual-design-system.md).

| Clave de Categoría (`snake_case`) | Etiqueta en Pantalla | Código Hexadecimal | Nombre de Color |
| :--- | :--- | :--- | :--- |
| `calle_anegada` | Calle anegada | `#2196F3` | Azul |
| `camino_interrumpido` | Camino interrumpido | `#F57C00` | Naranja |
| `desborde_rio_riacho` | Desborde de río o riacho | `#1565C0` | Azul oscuro |
| `vivienda_estructura_daniada` | Vivienda o estructura dañada | `#D32F2F` | Rojo |
| `arbol_caido` | Árbol caído | `#558B2F` | Verde |
| `obstruccion_desague` | Obstrucción de desagüe | `#00897B` | Turquesa |
| `poste_cable_caido` | Poste o cable caído | `#F9A825` | Amarillo ámbar |
| `danos_infraestructura_publica` | Daños en infraestructura pública | `#7E57C2` | Violeta |
| `corte_servicios_basicos` | Corte de servicios básicos | `#607D8B` | Gris |
| `otro` | Otro | `#757575` | Gris neutro |

### 2.3. Roles de Usuario (`UserRole`)
- `citizen`: Ciudadano registrado.
- `admin`: Operador técnico o autoridad con acceso al panel web.

## 5. Contratos de Funcionalidades Ciudadanas

### Endpoint: Enviar Reporte de Incidente
- **Ruta:** `POST /api/v1/reports`
- **Acceso:** Protegido (`Role: citizen` o `admin`).
- **Content-Type:** `multipart/form-data`
- **Reglas de Validación de Negocio:**
  1. `category`: Obligatorio, perteneciente al catálogo de categorías permitidas.
  2. `latitude` y `longitude`: Obligatorios, decimales válidos que **deben encontrarse dentro del polígono de Formosa**.
  3. `photo`: Archivo binario opcional (JPEG, PNG, WebP; máx. 5 MB).
  4. `comment`: Cadena de texto (máx. 1.000 caracteres). **Obligatorio si no se adjunta fotografía**.
  5. Si `category == "otro"`: El campo `comment` es **obligatorio** si no hay fotografía adjunta para describir el suceso.
  6. La fecha y hora son **generadas automáticamente por el servidor** (`created_at`).

#### Campos Multipart:
- `category` (string, ej: `"calle_anegada"`)
- `latitude` (float, ej: `-26.1852`)
- `longitude` (float, ej: `-58.1738`)
- `comment` (string, opcional si hay foto, ej: `"El agua supera la vereda e ingresa a los domicilios."`)
- `photo` (file, binario opcional)

#### Respuesta Exitosa (`201 Created`):
*Estructura exacta de la tarjeta de confirmación requerida funcionalmente:*
```json
{
  "confirmation": {
    "success": true,
    "message": "Reporte enviado correctamente",
    "report_id": "9f8e7d6c-5b4a-3f2e-1d0c-ba9876543210",
    "report_number": "#00142",
    "category": "calle_anegada",
    "category_label": "Calle anegada",
    "location": {
      "latitude": -26.1852,
      "longitude": -58.1738,
      "address_reference": "Av. 25 de Mayo y Calle Fontana, Formosa Capital"
    },
    "created_at": "2026-11-18T14:22:10.000Z",
    "status": "pendiente",
    "status_label": "Pendiente",
    "status_message": "El aviso fue recibido.",
    "photo_url": "https://xyz.supabase.co/storage/v1/object/public/incident-photos/reports/2026/11/9f8e7d6c.jpg"
  }
}
```

#### Respuestas de Error Comunes:
- `422 Unprocessable Entity` (Código: `OUTSIDE_TERRITORY`):
  ```json
  {
    "error": {
      "code": "OUTSIDE_TERRITORY",
      "message": "La ubicación seleccionada se encuentra fuera del territorio provincial de Formosa.",
      "details": { "latitude": -25.2987, "longitude": -56.8921 },
      "timestamp": "2026-11-18T14:22:10.000Z"
    }
  }
  ```
- `422 Unprocessable Entity` (Código: `COMMENT_OR_PHOTO_REQUIRED`):
  ```json
  {
    "error": {
      "code": "COMMENT_OR_PHOTO_REQUIRED",
      "message": "Debe proporcionar una fotografía o redactar un comentario descriptivo de la situación.",
      "details": null,
      "timestamp": "2026-11-18T14:22:10.000Z"
    }
  }
  ```

### Endpoint: Preferencia de Notificaciones Push *(ampliación del contrato, 2026-11-20)*
- **Ruta:** `PUT /api/v1/users/me/notifications`
- **Acceso:** usuario autenticado (`citizen` o `admin`).
- **Propósito:** registrar o quitar el teléfono que recibe las notificaciones de cambio de estado de los reportes propios. Es una notificación en la barra del celular (Expo Push → Firebase Cloud Messaging); no usa SMS, teléfono ni correo.
- **Request Body:**
```json
{
  "enabled": true,
  "push_token": "ExponentPushToken[xxxxxxxxxxxxxxxxxxxxxx]"
}
```
- **Reglas:**
  1. Con `enabled: true`, `push_token` es obligatorio y debe ser un token de Expo (`ExponentPushToken[…]`); si no lo es → `400 INVALID_INPUT`.
  2. Con `enabled: false` se borra el token guardado.
  3. Un mismo token pertenece a un solo usuario: si el teléfono inicia sesión con otra cuenta, se quita de la anterior.
- **Response (200 OK):**
```json
{ "enabled": true, "has_token": true }
```
- **Envío:** cuando `PATCH /admin/reports/{id}/status` llega con `notify_citizen: true` y el ciudadano tiene la preferencia activa, el backend envía en segundo plano la notificación «Reporte #00142 · Pasó a «En revisión». <comentario del operador>», con `data: { "type": "report_status", "report_id": "<uuid>" }`. Un fallo del envío no afecta el cambio de estado.
