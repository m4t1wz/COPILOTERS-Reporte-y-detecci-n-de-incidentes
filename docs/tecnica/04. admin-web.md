# 04. Especificación Técnica del Panel Web Administrativo — NEXO MAP (React)
## NEXO MAP — Sistema de Reporte y Seguimiento de Incidentes Territoriales (Formosa)

Este documento define la arquitectura técnica, estructura de componentes, identidad de marca, gestión de estado, integración cartográfica con MapLibre y consumo de servicios REST para el panel administrativo web de **NEXO MAP**.

### Identidad Visual y Logotipo en la Web
- **Nombre:** NEXO MAP Admin
- **Logotipo:** `Nexo_map.png` (situado en el Navbar superior izquierdo junto al isotipo de marca).
- **Favicon:** `Nexo_map.png` (en `admin-web/public/favicon.ico` / `Nexo_map.png`).

---

## 1. Arquitectura General y Tecnologías Seleccionadas

El panel administrativo es una Single Page Application (SPA) modular y responsiva orientada a operadores de emergencia y autoridades provinciales:

- **Framework y Bundler:** React 18 / 19 + Vite + TypeScript.
- **Enrutamiento:** React Router DOM v6 / v7 con rutas protegidas (`<AdminRoute>`).
- **Sistema Visual y de Diseño:** Implementación estricta de [docs/08. visual-design-system.md](08.%20visual-design-system.md): paleta institucional azul (basada en el logo) y blanco (`#0475EF` y `#FFFFFF`), tipografía **Inter** (pesos 400, 500, 600), iconografía lineal **Lucide Icons** (prohibición total de emojis), bordes sutiles en `#E8E5E5` y fondos en `#F7F7F7`.
- **Gestión de Estado Servidor:** TanStack Query v5 (React Query) para caché, revalidación en segundo plano y mutaciones optimistas.
- **Gestión de Estado Global / UI:** Zustand para sesión de usuario, preferencias y estado de modales.
- **Estilos y UI:** Tailwind CSS con tokens centralizados + componentes accesibles + `lucide-react`.
- **Cartografía Interactiva:** `react-map-gl/maplibre` + `maplibre-gl` (v4/v5).
- **Cliente HTTP:** Axios configurado con interceptores para inyección automática del token Bearer y manejo unificado de errores RFC 7807.

## 3. Enrutamiento y Protección de Rutas (`<AdminRoute>`)

Solo los usuarios autenticados con rol `"admin"` pueden visualizar las rutas del panel. Si un usuario no autenticado o con rol `"citizen"` intenta ingresar, es redirigido inmediatamente a `/login`.

```tsx
// src/components/layout/AdminRoute.tsx
import React from 'react';
import { Navigate, Outlet } from 'react-router-dom';
import { useAuthStore } from '../../store/auth-store';

export const AdminRoute: React.FC = () => {
  const { user, isAuthenticated, isLoading } = useAuthStore();

  if (isLoading) {
    return <div className="flex h-screen items-center justify-center"><Spinner /></div>;
  }

  if (!isAuthenticated || user?.role !== 'admin') {
    return <Navigate to="/login" replace />;
  }

  return <Outlet />;
};
```

## 4. Integración Cartográfica con MapLibre (`react-map-gl/maplibre`)

El panel administrativo implementa `react-map-gl/maplibre` para una integración declarativa con React.

### 4.1. Restricción de Navegación y Coordenadas de Formosa
- **Centro Geográfico:** Longitud: `-59.94836`, Latitud: `-24.67426` (Centro de la provincia).
- **Zoom Inicial:** Nivel `7.5` (muestra la provincia completa).
- **Límites Máximos de Desplazamiento (`maxBounds`):**
  Calculados con base en el BBOX de `formosa.json` con un margen de seguridad de 0.2 grados:
  `[[-62.6, -27.1], [-57.3, -22.2]]`.
  El usuario no puede arrastrar el mapa fuera de esta caja.

### 4.2. Efecto Visual de Máscara Invertida (Exterior Oscuro)
Para satisfacer el requerimiento de que *"por fuera esté en un color más oscuro"*, se aplica una capa `FillLayer` sobre la máscara invertida:

```tsx
// Capa GeoJSON de máscara exterior
<Source id="formosa-mask-source" type="geojson" data="/geo/formosa-mask.json">
  <Layer
    id="formosa-dark-outside"
    type="fill"
    paint={{
      'fill-color': '#0f172a',    // Slate 900 oscuro
      'fill-opacity': 0.65       // Oscurece el exterior destacando Formosa
    }}
  />
  <Layer
    id="formosa-boundary-line"
    type="line"
    paint={{
      'line-color': '#38bdf8',    // Borde celeste brillante
      'line-width': 2
    }}
  />
</Source>
```

### 4.3. Visualización de Zonas de Concentración (Clusters)
Las agrupaciones poligonales se renderizan como polígonos semitransparentes coloreados por categoría:

```tsx
<Source id="clusters-source" type="geojson" data={clustersGeoJson}>
  <Layer
    id="clusters-fill"
    type="fill"
    paint={{
      'fill-color': ['get', 'color'],
      'fill-opacity': 0.35
    }}
  />
  <Layer
    id="clusters-stroke"
    type="line"
    paint={{
      'line-color': ['get', 'color'],
      'line-width': 2,
      'line-dasharray': [2, 1]
    }}
  />
</Source>
```

### 4.4. Marcadores de Incidentes Individuales
Se representan mediante una capa vectorial `CircleLayer` de alto rendimiento para soportar miles de incidentes simultáneos sin caídas de framerate, coloreados con base en la propiedad `color` provista por la API:

```tsx
<Source id="incidents-source" type="geojson" data={incidentsGeoJson}>
  <Layer
    id="incidents-points"
    type="circle"
    paint={{
      'circle-radius': 7,
      'circle-color': ['get', 'color'],
      'circle-stroke-width': 2,
      'circle-stroke-color': '#ffffff'
    }}
  />
</Source>
```

---

### 4.5. Actualización y Reportes Finalizados
- El mapa operativo muestra por defecto los estados activos (la API excluye `resuelto` y `descartado`); el filtro «Estado» permite consultarlos explícitamente.
- Las consultas de incidentes y zonas se refrescan cada 60 s, al volver a la pestaña del navegador (`refetchOnWindowFocus`) y tras cada cambio de estado (`invalidateAfterStatusChange`).
- **No existe borrado de reportes** (decisión del 2026-11-20): `resuelto` y `descartado` son estados finales. El reporte y su historial se conservan por trazabilidad (`06` §3.4) y para el seguimiento del ciudadano en «Mis reportes». El contrato `02` no define `DELETE`. La limpieza de datos de prueba se hace por SQL (`supabase/checks/limpiar_datos_prueba.sql`).

## 5. Módulos y Páginas del Panel Administrativo

El panel administrativo comparte exactamente la misma identidad visual que la aplicación móvil: paleta basada en el azul principal del logo (`#0475EF`), blanco (`#FFFFFF`), fondo general (`#F7F7F7`), bordes discretos (`#E8E5E5`), tipografía Inter e iconografía Lucide. No se utilizan emojis en ninguna parte de la interfaz y los textos son estrictamente directos y funcionales, sin subtítulos innecesarios o frases decorativas.

### 5.1. Dashboard Principal (`DashboardPage.tsx`)
Ofrece una visión ejecutiva inmediata, sobria y ordenada:
1. **Tarjetas de Métricas:**
   - Construidas con fondo blanco (`#FFFFFF`), borde sutil de 1px en `#E8E5E5` y esquinas con redondeo moderado (`rounded-lg` / 8px).
   - Tipografía Inter Semibold (600) para cifras y Medium (500) para etiquetas en texto secundario (`#777777`).
   - Iconos vectoriales Lucide (trazo 1.75px) asociados a cada métrica, sin emojis.
   - Contadores incluidos:
     - Total de Reportes
     - Pendientes de Revisión (acento en amarillo ámbar `#F9A825`)
     - Incidentes Verificados (acento en verde `#558B2F`)
     - Incidentes en Seguimiento (acento en azul `#2196F3`)
     - Incidentes Resueltos (acento en texto principal `#252525`)
     - Reportes Descartados (acento en texto secundario `#777777`)
     - Zonas de Concentración Activas (acento en azul principal `#0475EF`)
2. **Mapa Operativo Integrado:** Visualización funcional de Formosa con el exterior oscurecido y los polígonos de concentración, sin marcos decorativos excesivos.
3. **Acciones Rápidas:** Enlaces limpios para filtrar la tabla hacia los casos pendientes más antiguos.

### 5.2. Gestión de Reportes (`ReportsPage.tsx`)
Tabla de datos interactiva orientada a la máxima legibilidad:
- **Barra de Filtros:** Controles en fondo blanco (`#FFFFFF`), bordes de 1px `#E8E5E5`, redondeo discreto (6px). Iconos Lucide `Filter` y `Calendar`. Sin descripciones redundantes.
- **Estructura de la Tabla:**
  - Encabezados con fondo `#F7F7F7`, bordes `#E8E5E5`, texto en Inter Medium 12px color `#777777`.
  - Filas con bordes inferiores sutiles `#E8E5E5`, efecto hover muy suave (`hover:bg-[#E2F9FE]/40`). Líneas predominantemente rectas para maximizar el orden visual.
  - Columnas:
    1. Identificador `#00000` (Inter Semibold, enlace directo en color `#0475EF`).
    2. Categoría (con indicador de color oficial y etiqueta en Inter Regular 14px).
    3. Ubicación Geodecodificada y coordenadas exactas. El panel no geocodifica: muestra el `address_reference` calculado por el backend (`03` §4.2) mediante `utils/address.ts`. Si la referencia está vacía, muestra las coordenadas. Si es la referencia sintética de contingencia (`Coordenadas: …` o `Ubicación Formosa (…)`), no repite las coordenadas debajo. El mismo criterio se aplica en la ficha, el popup del mapa y las acciones rápidas.
    4. Fecha y Hora local (`DD/MM/AAAA HH:MM`).
    5. Miniatura de fotografía (si existe) con esquinas redondeadas a 4px.
    6. Estado actual (badge rectangular con bordes sutiles, no cápsula ovalada).
    7. Acciones (Botón «Gestionar» con fondo blanco, borde `#E8E5E5`, hover con fondo `#E2F9FE`).
- **Paginación:** Selector de cantidad por página y botones siguiente/anterior con iconos Lucide `ChevronLeft` y `ChevronRight`.

### 5.3. Ficha Detallada del Incidente (`ReportDetailPage.tsx`)
Muestra la información completa y permite las acciones operativas:
- **Panel Izquierdo:**
  - Identificador `#00142`, categoría y estado actual.
  - Fotografía en alta resolución con visor modal limpio.
  - Comentario original del ciudadano denunciante en tarjeta blanca `#FFFFFF` con borde `#E8E5E5`.
  - Datos del ciudadano (Nombre, teléfono para contacto directo en emergencias).
- **Panel Central (Mapa):** Vista satelital/vectorial centrada en el punto exacto del incidente con el polígono provincial de fondo.
- **Panel Derecho (Acciones y Trazabilidad):**
  - **Botón Destacado «Actualizar Estado»:** Fondo azul principal `#0475EF`, texto blanco `#FFFFFF`, hover en azul marino `#091B3B`, esquinas moderadas (`rounded-lg` / 8px).
  - **Historial y Auditoría (`AuditTimeline.tsx`):**
    - Muestra la secuencia de cambios de estado ordenados cronológicamente (del más antiguo al más reciente).
    - Línea vertical continua en `#E8E5E5` con nodos circulares limpios.
    - Nombre del operador que efectuó cada modificación en Inter Medium (500).
    - Comentario administrativo registrado en caja con fondo `#F7F7F7` y borde `#E8E5E5`.
    - Fecha y hora exacta de cada hito.

## 6. Flujo del Modal de Actualización de Estado (`StatusModal.tsx`)

El formulario de actualización de estado valida las reglas de transición antes de despachar la petición a `PATCH /api/v1/admin/reports/{id}/status`:

1. **Selector de Nuevo Estado:** Solo muestra estados válidos según la máquina de estados (ej. si está en `pendiente`, solo permite seleccionar `en_revision` o `descartado`).
2. **Área de Texto de Comentario Administrativo:**
   - Campo de texto obligatorio con placeholder: *"Escriba las observaciones operativas que serán visibles para el ciudadano..."*
   - Validación de longitud mínima (5 caracteres) y máxima (1000 caracteres).
3. **Casilla de Verificación de Notificación:** *"Notificar al ciudadano sobre este cambio de estado"* (marcada por defecto).
4. **Respuesta Visual:** Notificación toast de éxito (con `sonner` o `react-hot-toast`) y revalidación automática de la consulta en React Query para refrescar la tabla y el mapa sin recargar la página.
